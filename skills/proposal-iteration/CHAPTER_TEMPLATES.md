# 各章節寫作公式（補 ARCHITECTURE 的具體 how）

> 沉澱製造業客戶 / 線上課程客戶實戰 — 下次接案每個章節都有具體寫法套路，不用重新想。

## §1 Foreword 開場（立場 framing）

### 公式

```
[Section label] 00 · Foreword
[h-rule]

[大標 serif] 一句「這份文件的立場宣告」

[段落 1] 引用 X/X 會議客戶說的核心關鍵字（3 個 strong）
    + 「但『應該長什麼樣子』這個問題，我們認為不該由您回答 — 該由我們先提出一版完整規格，您負責『指出哪裡不對』。」

[段落 2] 「所以這份文件的設計是：把整個系統的 {元素 1}、{元素 2}、{元素 3} 都先『組裝』出來，
        讓您看到『如果這樣做，會長什麼樣』。每一個段落您都可以說『這個改』、『這個拿掉』、『這個我想要更多』 —
        我們修到您滿意，雙方對規格無爭議即進入合約。」

[段落 3] 「另外要先講清楚：這個案子的真正價值不在『{表面需求}』，而在『{深層需求}』 —
        {更深層的洞察}」
```

### 範例（製造業客戶）

> 立場：這份文件不是「報價單」，是「我們先把系統組裝給你看」。
>
> 引用：「90% 紙本 IDP 流於形式」、「1–2 年的長期追蹤才是真正的痛點」、「不要花俏功能，要簡單能用」
>
> 深層：真正價值不在「把紙本表單變成網頁」，而在「讓系統替企業 HR 在 3/6/9/12 月主動把該追蹤的人、該回饋的事準確送到對的人手上」— 連續跑 1-2 年不出錯、60 歲 HR 也會用。

### 關鍵元素檢查
- [ ] 一句立場宣告（「不是 X，是 Y」對比句型）
- [ ] 至少 3 個客戶會議原話（strong 標示）
- [ ] 「我們修到您滿意 + 無爭議入合約」承諾
- [ ] 「真正價值不在 X，而在 Y」深層洞察句

⚠️ Foreword 沒有客戶會議原話 = 整份文件失去 anchor。一定要從 `01_客戶資訊/會議記錄_X.md` 翻出來引用。

## §2 規格表設計（Part 1 · 表單規格頁）

### 每個表單規格頁的公式

```
[Label] 02 · Functional Spec · Part 1 · 表單 0X
[h-rule]

[h2 serif] 表單 0X · {表單名}（如「HR 催件主控台」）

[小標 + 描述] 對應 Excel：{對應的客戶原 Excel 名稱}

[一段話] 解釋這張表的目的（HR 用來幹嘛、為什麼存在）

[規格表]
| 欄位 | 邏輯 |
|---|---|
| {欄位名 1} | {三態邏輯} 或 {自動判定條件} |
| {欄位名 2} | {O/X 自動標示} 或 {使用者輸入} |
| {欄位名 3} | {計數 +1，可設「達 N 次自動通知」} |
| ...      | ... |

[權限規則 box - 灰底 cream]
誰能讀 / 誰能寫 / 誰能改 — 角色矩陣對應
```

### 範例（製造業客戶 · 表單 02 HR 催件主控台）

```
欄位          邏輯
IDP 面談狀態   三態：尚未面談 / 修改中 / 已完成（系統自動判定）
繳交狀態      O / X 自動標示
催繳次數      每次催繳 +1，可設「達 3 次自動通知 HR 主管」
```

### 「不含」欄位設計（A 方案頁必用）

A 方案功能清單頁用 `grid-cols-3`，前半綠勾 ✓、後半紅字 — 標示「升級到 B 才會有」：

```html
<div>✓ IDP 表單線上化（4 個發展項目）</div>
<div>✓ 三角色權限（學員 / 主管 / HR）</div>
<div>✓ HR 繳交狀況檢視頁</div>
<div style="color:var(--rust);">— 不含 Email / LINE 通知</div>
<div style="color:var(--rust);">— 不含 Excel 匯出</div>
<div style="color:var(--rust);">— 不含一鍵催繳功能</div>
```

⚠️ 紅字「不含」是 A 方案的關鍵 — 客戶看完會自己往 B 方案走。**不是負面語氣，是 disqualify 武器**。

## §3 Visual Mockup 章節公式（Part 2 · 每張 mockup）

### 每個 Visual 頁的公式

```
[Label] Visual 0X · {角色}視角
[h-rule]

[h2] {一句場景描述：在哪 + 做什麼 + 看到什麼}
    例：「主管登入後看到『我的部屬』 — 3-4 位部屬的 IDP 進度、誰要回饋、誰逾期，
    主管可在表格中逐一進入學員的回饋表單填寫。」

[左欄 5 col] UI mockup (browser-frame + URL bar + app 內容)
[右欄 7 col] 文字說明（這個畫面解決什麼痛點 + 3-5 個 bullet）

[底部 box]「為什麼這頁重要」一句話
```

### Mockup 數量原則
- 系統案：5-7 個 Visual（每角色一張 + 報告 + 通知範例 + RWD 適配）
- 前端網頁案：3-4 個（首頁 + 報名頁 + 後台 + RWD）

### 必有的角色 mockup
- **學員 / 用戶視角**（填表、瀏覽）
- **主管 / 老師視角**（多部屬管理）
- **HR / 客戶後台**（控制中心）
- **SaaS 跨企業視角**（如果有 C 平台化方案）⭐
- **第三方角色**（教練 / 外部專家，若有）
- **三平台 RWD**（手機 / 平板 / 桌機並陳）
- **報告 + 通知範例**（Email/LINE 文案實體）

## §4 三方案 A/B/C 寫作公式

### 三方案命名邏輯（兩 Track 不同）

**Track A · 系統案** — 規模差別：
```
A · 電子化  「紙本進螢幕」     基礎功能
B · 自動化 ⭐「系統會自己跑」    +追蹤排程、通知、報表
C · 平台化  「SaaS 多企業」    +多企業隔離、跨業 benchmark
```

**Track B · 前端網頁案** — 工法差別：
```
A · 套模板    把舊版視覺當模板套上新內容（最快、最便宜）
B · 改原碼 ⭐ 拿原始碼一行一行修、保留動畫（推薦）
C · 重新設計  同主題全新精美設計 + 完整後台（最高檔）
```

### 每個方案的「故事頁」公式

```
[左欄 5col]
  巨大字母 A/B/C (num-display, 120px, brand color)
  serif 「方案名」
  小字「『XX』式 framing」
  h-rule 80px
  巨大報價 num-display 36px
  工期小字

[右欄 7col]
  serif 大標：一句概括「這方案解什麼問題」
  段落 1：紙本/現況的痛點
  段落 2：這方案做什麼解
  「適合您 if」box (cream + brand color):
    · 條件 1
    · 條件 2
    · 條件 3
  小字「不適合您 if：您希望 X — 直接看 {下一級方案}」

[底部] 功能清單 grid-cols-3 ✓✓✓ — 紅字
```

### 「適合您 if / 不適合您 if」寫法範例

**A · 電子化**：
> 適合您 if
> · 想先驗證「IDP 線上化的接受度」，催繳/提醒/匯出之後再升級
> · 內部還沒準備好把 IDP 變成核心制度
> · 想用最小成本先把紙本痛點解掉
>
> 不適合您 if：您希望系統替 HR 自動催繳、匯出月報給董總 — 直接看 B；若您要系統自動推薦課程，直接看 C。

⚠️ 「不適合」段尤其重要 — **主動 disqualify 不對的客戶**，反而讓對的客戶覺得「這團隊很懂自己的位置」。

### 三方案比較表格式

```
| 比較項目 | A · 電子化 | B · 自動化 ⭐ | C · 平台化 |
|---|---|---|---|
| 核心系統 | 基礎 IDP 流程 | + 月度報表 + AI 評語 | + 多分公司 |
| 月度調整 | 2hr | **4hr** | 8hr |
| 教育訓練 | 1 場 2hr | **2 場 + 影音** | 4 場 + 客製 |
| 支援回應 | 工作日 24hr | **工作日 4hr** | 24/7 2hr |
| 年度改版 | 無 | 無（額外收費 5-10 萬）| **含 1 次** |
| 總工期 | 35 天 | 45 天 | 60 天 |
```

⚠️ B 方案那欄整列粗體 + cream 高亮 — 視覺上 anchor「推薦選這個」。

## §5 加急選項頁公式

### 加急表格格式

```
| 檔位 | 標準工期 | 標準價 | 加急工期 | 加急價（×1.25） |
|---|---|---|---|---|
| A 基礎版 | 2 個月 | NT$ 480,000 | 1.5 個月（省 2 週）| NT$ 600,000 |
| B 標準版 ⭐ | 3.5 個月 | NT$ 820,000 | 2.5 個月（省 1 月）| NT$ 1,025,000 |
| C 完整版 | 5 個月 | NT$ 1,320,000 | 4 個月（省 1 月）| NT$ 1,650,000 |
```

### 「為什麼加急會多 25%」說明 box（必有）

```
為什麼加急會多 25%

加急不是「我們本來就能做更快但藏起來」 — 加急是
**追加一位資深工程師平行開發**，把可平行的模組
（前端 vs 後端、IDP vs 報表）拆給兩人同步處理。
費用反映的是「多請一個人」的成本，而非「我們之前在慢慢做」。
若您沒有時程壓力，**標準工期是最划算的選擇**。
```

⚠️ 任何溢價條款都要主動解釋「為什麼貴」— 透明 = 信任。

## §6 付款方式頁公式

### 三階段表格

```
| 階段 | 比例 | 觸發條件 |
|---|---|---|
| 簽約金 | 40% | 合約簽署 + 規格凍結 + 啟動開發 |
| 期中款 | 30% | Alpha 版交付驗收（系統可登入、核心流程可走通） |
| 尾款 | 30% | 正式上線 + 雙方驗收簽收 |
```

### 「為什麼是 40/30/30」說明（必有）

```
為什麼是 40 / 30 / 30

簽約金 40% 用於 **規格凍結 + 團隊正式 onboard**
（含資深工程師排程鎖定、設計資源預留）；

期中款 30% 對應 **Alpha 版驗收**
（您能登入實際系統並走完核心流程）；

尾款 30% 對應 **正式上線 + 雙方驗收簽收**。

若加購維運，**前 3 個月免費**，第 4 個月起依您選的維運級別開始月結。
```

### 比例選擇
- **40/30/30** — 系統案標準（需要鎖團隊資源）
- **30/40/30** — 設計案標準（產出後段比較吃力）
- **30/30/40** — 客戶不確定性高、要保留壓力（少用）
- **50/50** — 很小的案件（< 10 萬）

## §7 服務承諾與驗收條件（信任建立的關鍵）

### 必有的承諾條款


### 三個必有的承諾元素
1. **「您不接受系統，我們不收尾款」** — 把驗收主動權交客戶
2. **「維運合約一年一簽、不綁約、不自動續訂」** — 解除客戶長期承諾恐懼
3. **「30 天前雙方檢視續約」** — 給退出機制

## §8 商業價值章節公式（Part 3 · ROI）

### 3 個 ROI 角度（永遠這 3 個）

#### ① 直接成本對比
「{客戶角色} 過去每月花在 {重複勞動} 的時間 ≈ {X}%。系統接手後，{客戶角色} 把時間花在 {高價值工作} — {帶來什麼新收入/節省}。」

#### ② 資料價值 / 規模放大
「12 個月累積的 {資料類型} 是您談 {續約 / 新客戶 / 升級} 的真實成績單。」

#### ③ 平台事業的可能
「同一套系統可以服務 1 家 / 10 家 / 100 家客戶。您未來每多接一個，邊際成本接近零。報價看起來高，但攤到未來 3 年、N 個客戶 — 您會發現這是您買過 ROI 最高的工具之一。」

## §11 客戶會議記錄怎麼變成 Foreword 原話

### 流程

1. **每次會議後**：寫 `01_客戶資訊/會議記錄_{YYYY-MM-DD}.md`
2. **記錄重點**（不要逐字稿）：
   - 客戶說的「我們最痛的是 X」「我們不要 Y」「我們希望 Z」短句
   - 客戶用的特殊詞彙（如「IDP」「流於形式」「業務系統」）
   - 客戶提到的時間錨點（「年底前要 ___」）
   - 客戶提到的競品（「上次找過 XX 報 YY 萬」）
3. **產 Foreword 時**：挑 3 句最有 anchor 力的短句，**逐字引用**（strong 標示）

### 範例 — 製造業客戶 從會議萃取

| 客戶會議原話 | 用在哪 |
|---|---|
| 「90% 紙本 IDP 流於形式」 | Foreword 引言 1 |
| 「1–2 年的長期追蹤才是真正的痛點」 | Foreword 引言 2 |
| 「不要花俏功能，要簡單能用」 | Foreword 引言 3 |
| 「不接受第三方傳話」 | Why Us 03 段（您買的不是專案、是長期夥伴） |
| 「售後要回應及時」 | Why Us 03 段 |

⚠️ **沒有會議原話 = 整份文件失去 anchor 力**。第一次接觸就要錄音/逐筆記。

## §12 跨章節必有的 7 種 box

每份完整需求書必有這 7 個淺色 box（cream + gold 左邊框）+ 3 個黑底 box（ink + gold 左邊框）：

### 淺色 box（cream + gold 左邊框）
1. ✅ 「為什麼是這份文件」（Foreword）
2. ✅ 「適合您 if / 不適合您 if」× 3（A/B/C 各一）
3. ✅ 「為什麼推薦 B」（B 故事頁）
4. ✅ 「為什麼加急會多 25%」（加急頁）
5. ✅ 「為什麼是 40/30/30」（付款頁）
6. ✅ 「為什麼是這個價格」（Why Us 頁）

### 黑底 box（ink + gold 左邊框）
1. ✅ 「驗收承諾 · 您不接受系統我們不收尾款」（驗收頁）
2. ✅ 「合約週期 · 一年一簽、不綁約」（維運頁）
3. ✅ 「為什麼接這個案」（About Us 結尾）

⚠️ 缺任何一個都會讓需求書「少一塊」— 客戶會說不出哪裡怪、但感覺薄。
