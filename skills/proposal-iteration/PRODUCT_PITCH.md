# PRODUCT_PITCH.md — 產品銷售型提案書（開案 pitch，非結案報告）

沉澱自 2026-07 短影片腳本客戶生成器案：產品已做完，但要「當成全新開案」賣給對方。
完整實例：`feature14_may_viral_script/02_需求書/短影片腳本生成器_產品提案書.html`（17 頁，含標註式虛擬圖 + Live Run 逐站截圖 + S06b fine-print 頁）。

適用場景：**東西已經存在（或接近存在），但文件要說服對方「購買一個產品」而不是「驗收一個專案」。**
包含：自建工具轉賣、SaaS 授權、模板/系統轉售、demo 先行的搶案。

---

## §1 開案 pitch vs 結案報告 — 語氣的根本差別

| | ❌ 結案報告語氣 | ✅ 開案 pitch 語氣 |
|---|---|---|
| 起手 | 「我幫妳做好了 XXX」 | 「妳的產能卡在哪一關」（痛點先行）|
| 產品段 | 「已完成的功能清單」 | 「這個產品長什麼樣、為什麼它做得到」 |
| 已做完的事實 | 藏不住也不用藏 | 轉成**武器**：真的跑一輪產線、把每一站的實際畫面截進文件（「以 XX 為題實際跑一輪，下面全是實際畫面」）。⚠️ **不要寫「提案會議上示範給妳看」**——文件要自證，不依賴會議場景（May 案客戶明確要求拿掉）|
| 收尾 | 「請驗收 / 請回饋」 | 「三步到手 + 會前想好三件事（Q1–Q3）」 |

**Why**：說「我做完了」= 邀請對方進入驗收心態（挑毛病、殺價、「這本來就該有」）；
說「這個產品存在、live demo 隨時可跑」= 零風險證明 + 購買心態。
同一個事實，framing 決定談判位置。

**11 個必清字眼之外，pitch 型再加清單**：「已為您完成」「交付成果如下」「本次開發」→ 全改成產品視角（「這套工具會…」）。

## §2 產品敘事收斂 —「一條產線」而不是「N 個模組」

製造業客戶 是系統案（模組清單合理）；產品 pitch 相反 — **模組列表 = 認知負擔 = 「看起來很複雜我學不會」**。

收斂公式：
1. 主敘事 = **一個入口 → 一個產出**（May 案：「一個輸入框 → 10–15 支可拍腳本」）。
2. 功能變成**產線站點**（① 輸入 ② 拆解 ③ 生成 ④ 輸出），不是並列模組。
3. 技術性副產品翻譯成**資產敘事**：cache 層 →「爆款資料庫：免重拆免重付、別人抄不走的資產」；搜尋功能 →「爆紅雷達：永遠跟著當下風向」。
4. **App 介面要跟提案敘事一致**：提案說一條產線，產品就真的收斂成一頁一個輸入框（May 案為此把 生成/一鍵爆款/靈感池 三頁合併成一頁再截圖）。文件跟產品互相背書。
5. 「妳的一天會變成這樣」5 步時間軸（每步標分鐘數）— 把產線翻譯成生活場景。

## §3 產品證據系統 — 標註式虛擬圖開場 + Live Run 逐站截圖

**產品 pitch 最大死罪：整本沒有產品的臉。** 頁面下半空 30–40% 時，先想「補產品證據」而不是「補文字」。

⚠️ **裸截圖陷阱（May 案客戶原話）**：「這會讓人看不懂到底是幹嘛的——觀眾還沒用過，不知道有哪些功能，也不知道什麼是『靈感池』。」
第一次見產品的人看 hero 截圖 = 一堆看不懂的名詞。**開場要用標註式虛擬圖，真實截圖放後面的逐站 walkthrough。**

標準配置：
| 位置 | 圖 | 作用 |
|---|---|---|
| S01b（Foreword 後獨立一頁）| **標註式虛擬圖**：HTML/CSS 照實際介面畫、每個區塊編號①–⑤、下方 legend 逐號解釋功能（含解釋自創名詞如「靈感池」）| 「一張圖看懂它是什麼」— 零前置知識可讀 |
| S02b–d（產品總覽後 2–3 頁）| **Live Run 逐站真實截圖**：以一個具體題目真跑一輪，每站一張（研究結果 → 撈片 log → 影片牆 → 拆解報告），圖說寫「這一站在幹嘛＋為什麼可信」| 「不是概念圖，是真的跑出來的」— 過程證據 |
| S03 差異化章節尾 | 成品雙圖並排（產出物 + 交付格式）| 「下面就是它交出來的東西」— 輸出端 |

虛擬圖 CSS 組件：`.mock-app`（1.5px ink 邊+硬影）、`.mock-zone`（左留 48px 放編號徽章）、`.mock-badge`/`.ml-num`（黑底金字圓徽）、`.mock-chip`/`.mock-card`/`.mock-input` — 完整實作見 May 案 HTML。
截圖太窄的欄位卡片（如 grid 裡一格 177px）不能用 — 找展開後的全寬區塊（給它塞 id 再 `#id` 截）。

截圖 SOP：
- Playwright `scale: "device"`、viewport 1440×1000，存進 `02_需求書/assets/`
- **截圖前必移除 dev 雜訊**：`document.querySelector('nextjs-portal')?.remove()`（Next.js dev tools 的 N 鈕），localhost 截圖第一次幾乎必中招
- 包 browser-chrome 外框（`.shot-frame`：1px ink 邊 + `6px 6px 0 rgba(ink,0.08)` 硬影 + 三圓點 bar + 標籤文字），配 `.shot-cap` 圖說 — 圖說要**導讀畫面**（上/中/下各是什麼），不是重複標題
- CSS 記得 `page-break-inside:avoid`

## §4 三種擁有方式 — 產品轉售定價 A/B/C

跟服務案 A/B/C（0.95× / 1.7× / 2.6×）不同，產品轉售案軸線是**擁有權深度**。

⚠️ **方向修正（May 案客戶拍板）**：一開始做成「自用最便宜、轉售加價」被打回。正確邏輯是**「轉售版靠抽成回收，所以前期可以更便宜」**——自用版反而是乾淨的高錨：

| 方案 | 定位 | 定價邏輯 | May 案實例 |
|---|---|---|---|
| A · 自用版（推薦）| 一筆結清、永久自用、不牽扯任何拆帳 | **基準高錨** | NT$150,000 |
| B · 轉售版 | 前期最低、可賣同行 | **前期比 A 便宜**（用抽成補回來），**每套抽 30%** | NT$120,000 + 30%/套 |
| C · 買斷版 | 自由賣給任何人、零拆帳 | 讓 break-even 落在「認真賣就划算」的量 | NT$250,000 |

配套紀律：
- **行情錨放 PART divider 上**：「這套工具從零開發一次的市場行情約 NT$X–Y」（May 案 25–35 萬）— 讓 A 價看起來像撿到
- **划算點要自己算給對方看**（S06）：「只要妳總共賣超過約 NT$430,000（例如 13 套 × 3.5 萬），C 就比 B 便宜」— 主動算 = 誠實感 + 幫對方想像賣起來的樣子
- C 買斷版必標三件事：**可自由賣給任何人**、**含多帳號系統方便開帳號給買家**、**保固期後維修不包含**
- 轉售規則表逐項白紙黑字：費用付法 / 轉售權範圍 / 拆帳規則與對帳頻率 / 維修範圍誰扛
- 一句話選版公式收尾：「只想自己用 → A；想賣、想壓低前期投入 → B；確定要賣、不想被抽 → C」

**Fine-print 頁（S06b）必加** — 買軟體最常吵的三件事，白紙黑字寫在前面，一頁講完：
1. **維修保固範圍**：只涵蓋「目前交付的成果」＝個人使用程式本體（＋B/C 的多帳號系統）；新功能、介面客製、買家特殊需求另行報價。30 天保固後的處理方式逐方案列表。
2. **AI 使用費誰付**：買方申請**自己的 API key**、費用直付 AI 服務商（幾百元/月等級）；**轉售出去的每一套 = 買家綁自己的 key 各付各的**，賣越多不會回頭算到賣方頭上——這句要主動講，拆掉隱形恐懼。
3. **教學**：交付含一次完整教學（60–90 分鐘視訊實操）＋圖文操作手冊，手冊可轉給買家用。
收尾一句話總結三條都寫進合約。

## §5 養得起敘事 — 買軟體的人怕的不是價格，是月費

非技術買家的隱形恐懼：「買了之後每個月要花多少養它？壞了誰修？」
必有一頁**接手後的每月營運成本表**（項目 / 每月費用 / 說明），總計刻意壓出「幾百元等級」的結論句，
對比錨 =「一位兼職小編的月薪」。維護方案做成**選配**（「不買也完全不影響運作」）— 可退場的選項比強迫的月費好賣。

回本邏輯一句話化：「只要它每個月幫妳省下兩個工作天，它就已經值回票價」。

## §6 收尾 — 三步到手 + Q1–Q3

- 「下一步」永遠是**三步**（試用 → 選方案談條件 → 簽約交付），每步標時間，第一步必須零門檻（「妳先實際用一輪，用過才算數」）
- 「會議前想請妳先想好的三件事」Q1–Q3：把 A/B/C 的決策題提前塞進對方腦袋，會議就從「要不要買」變成「買哪個」
- END 金句公式：肯定對方已有的 + 指出唯一缺口 =「妳的方法論已經驗證過會贏，缺的只是一台讓它日夜不停跑的機器 —— 它就在這裡。」
