# 產需求書完成度 Checklist（防漏清單）

> 寫完 1 份需求書送客戶前一一勾，少一項都會減損品質。

---

## A · 立場與情感（Anchor 武器）

- [ ] **Foreword 引用 ≥ 3 句客戶會議原話**（strong 標示，從 `01_客戶資訊/會議記錄_*.md` 翻）
- [ ] **「不是 X，是 Y」立場對比句**（如「不是報價單，是組裝給你看」）
- [ ] **「真正價值不在 X，而在 Y」深層洞察句**
- [ ] **「我們修到您滿意 + 無爭議入合約」**承諾
- [ ] **「為什麼接這個案」客製化 box**（每個案點出該客戶獨有的價值）

---

## B · 規格深度（系統案必有）

- [ ] **角色權限矩陣表**（學員 / 主管 / HR / 管理員等）
- [ ] **多重角色設計**（同人可能多角色）
- [ ] **主要表單規格頁 ≥ 5 張**（拆多頁、每頁一個表單）
  - [ ] 欄位 / 邏輯 / 三態判定 / 自動標示
- [ ] **12 個月時間軸**（每個觸發點：3/6/9/12 月）— 系統案
- [ ] **數據儀表板規格**（哪些 KPI 數字、誰看得到）
- [ ] **服務範圍與權責劃分**（我們做什麼 / 客戶做什麼）

---

## C · 視覺答覆（讓客戶「看見」）

- [ ] **Visual mockup ≥ 5 個角色介面**（系統案）/ **≥ 3 個頁面**（前端網頁案）
- [ ] **三平台 RWD 並陳**（手機 / 平板 / 桌機）
- [ ] **報告 + 通知範例**（Email / LINE 文案實體）
- [ ] **每張 mockup 都用 .browser-frame + URL bar 包裝**
- [ ] **每張 mockup 旁有「這個畫面解決什麼痛點」說明**

---

## D · 商業價值（賣 ROI）

- [ ] **3 個 ROI 角度**（直接成本對比 / 資料價值 / 平台事業可能）
- [ ] **對比 in-house dev 成本**（年人力 100-150 萬）
- [ ] **未來 3 年攤算 ROI**（總投資 / 客戶數 / 邊際成本）

---

## E · 報價結構（決策資訊）

- [ ] **A/B/C 三方案命名邏輯一致**
  - 系統案 = 規模差別（電子化/自動化/平台化）
  - 前端網頁案 = 工法差別（套模板/改原碼/重新設計）
- [ ] **B 主推方案視覺 anchor**（黑底 + gold 文字、⭐ 標示、cream 高亮）
- [ ] **每個方案故事頁**（A/B/C 各 1 整頁 · serif 大標 + 巨大字母 + 報價）
- [ ] **「適合您 if / 不適合您 if」**× 3（A/B/C 各一組）
- [ ] **三方案比較表**（功能 / 工時 / 支援級別差異）
- [ ] **加急選項**（×1.25 or ×1.5 + 「為什麼會多」說明）
- [ ] **維運級別表**（建議搭配 A/B/C）— 系統案
- [ ] **付款方式 40/30/30**（含「為什麼這比例」說明）
- [ ] **市場價格對比 5 路線**（依案件 Track 選競品）
- [ ] **「為什麼是這個價格」 5 段論述**（系統案）/ **3-4 段**（前端網頁案）

---

## F · 公司介紹（Anchor 信任）

- [ ] **大廠背景三家 brand + 括號描述**
  - Appier（台灣 AI 獨角獸 · 東京交易所上市）
  - GoFreight（YC 物流 SaaS · 北美主力客戶）
  - 字節跳動（TikTok 母公司 · 大型流量產品）
- [ ] **3 卡片定位**（第 3 張永遠黑底 + gold 文字差異化武器）
- [ ] **相近案例表 5 個**（依相似度 ★★★/★★/★ 排序）
- [ ] **每個案例都標明「= XX 雷同」「= 對應 YY」**對應關係

---

## G · 信任建立（必有的承諾）

- [ ] **驗收承諾**：「您不接受系統，我們不收尾款」
- [ ] **合約週期**：「一年一簽、不綁約、不自動續訂」
- [ ] **退出機制**：「合約到期前 30 天雙方檢視」
- [ ] **CONFIDENTIAL** 底部標明文件僅供雙方使用

---

## H · CTA 與結尾

- [ ] **Next Step 大標**：「下一步只有一件事 —— 告訴我們您要 A、B 還是 C」
- [ ] **三方案卡片回顧**（含月費、適合誰、核心能力）
- [ ] **不要 instruct 客戶怎麼回**（讓他用舒服的方式即可）
- [ ] **「期待與您合作」結尾**
- [ ] **結尾頁三 metadata 欄**：案件編號 / 文件性質 / 下一里程碑

---

## I · 對外語氣紀律（14 個必清字眼 + 技術細節）

對外送出前 grep（升級版）：
```bash
grep -niE "v[0-9]\.|draft|草案|草稿|修訂版|提供中|TBD|待補|@example|xxx|v2 然後|請標註修改處|標註修改|簽約後|然後就簽約" *.html
grep -niE "PostgreSQL|MySQL|SQLite|Redis|nginx|Docker|Kubernetes|JWT|OAuth|REST API|GraphQL|schema|SLA [0-9]|Fly\.io|Vercel|AWS|GCP|deploy|CDN" *.html
```

### 版本/草稿/誘導字眼
- [ ] `<title>` 無 v / 需求設定書 / Draft
- [ ] 內文無「v1 文件」「v1 草案」
- [ ] 結尾頁無「Draft / 修訂版 / 待客戶回饋迭代」
- [ ] CTA 寫「出具合約草案」非「出修訂版」
- [ ] CONFIDENTIAL 寫「僅供…使用」非「提案草案」
- [ ] **無「v2 然後就簽約」字眼**（把客戶當階段砲灰、傷專業度）
- [ ] **無「請標註修改處」「請以修改方式回覆」**（被動式、引導客戶當校稿員）

### 技術內幕（對外必砍）
- [ ] 無 DB schema 細節（PostgreSQL / MySQL / 資料表結構）
- [ ] 無認證機制具體實作（JWT / OAuth / Session token）
- [ ] 無 SLA 具體數字（99.95% / RTO 4hr 之類，可寫「24h 內回應」不寫技術 SLA）
- [ ] 無部署架構（Fly.io / Vercel / AWS / Docker / Kubernetes / nginx）
- [ ] 無 API 規格（REST / GraphQL / endpoint 列表）
- [ ] 無 CDN / 雲端服務商名稱
- [ ] 維運費對齊（A/B/C 月費跟維運頁級別一致）
- [ ] 維運加值不寫死月費數字

### 一致性
- [ ] CTA 頁無 TBD 聯絡資訊
- [ ] 封面頁數對得上 PDF 實際頁數
- [ ] 內文無寫死「後 X 頁」「第 Y 頁」
- [ ] 比較表/CTA/總覽的 A/B/C 數字三處一致

---

## J · 美術品質（9 個禁忌）

- [ ] 沒有 PPT 風格（陰影、漸層、玻璃擬態）
- [ ] 沒有 emoji 裝飾（除 ⭐ 主推徽章）
- [ ] 沒有彩虹色 palette（brand-locked 7 色內）
- [ ] 正文左對齊（不要中央對齊大段）
- [ ] `line-height` ≥ 1.6（中文）
- [ ] padding ≥ 60px（A4 左右）
- [ ] 章節間有 cover 頁過渡
- [ ] 沒有對外露版號 / Draft / 修訂版
- [ ] 沒有寫死頁碼參照

---

## K · 跨章節必有的 box

- [ ] 「為什麼是這份文件」（Foreword cream box）
- [ ] 「適合您 if / 不適合您 if」× 3（A/B/C cream box）
- [ ] 「為什麼推薦 B」（B 故事頁 cream box）
- [ ] 「為什麼加急會多 25%」（加急頁 cream box）
- [ ] 「為什麼是 40/30/30」（付款頁 cream box）
- [ ] 「為什麼是這個價格」（Why Us 頁 cream box）
- [ ] 「驗收承諾 · 您不接受系統我們不收尾款」（ink 黑底 box）
- [ ] 「合約週期 · 一年一簽」（ink 黑底 box 或 inline）
- [ ] 「為什麼接這個案」（About Us 結尾 ink 黑底 box）

---

## L · PDF QA 三件套

- [ ] `_build_official.py` 跑完無 OVERFLOW
- [ ] 無真實 WIDOW（false positive 章節 cover 忽略）
- [ ] grep 無寫死「後 X 頁」「第 Y 頁」
- [ ] 每頁右下角金色頁碼（封面跳過）
- [ ] 主層 PDF 檔名無版號（`{客戶}_{產品}_提案書.pdf`）

---

## M · 送出前最後 5 個複查（mandatory）

- [ ] 客戶名稱拼字正確（製造業客戶 vs 製造業客戶人事顧問 vs 製造業客戶人事顧問股份有限公司）
- [ ] 報價數字三處一致（總覽 / 故事頁 / CTA 頁 / 比較表）
- [ ] Email 附件檔名 = 主層 PDF 檔名（沒拿到舊 _versions/ 檔）
- [ ] Email 主旨 / 內文不提「v1.X」「修訂版」
- [ ] 已 close brace test：每段「為什麼 X」都有對應的「答案 Y」（不是只有問題沒答案）
